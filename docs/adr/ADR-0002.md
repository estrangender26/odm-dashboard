# ADR-0002 — Optional Parallel MCP web-search provider

**Status:** Proposed  
**Date:** 2026-10-17  
**Layer:** Product Platform (ODM Dashboard AI assistant)

## Context

The assistant already retrieves live web evidence through `api/web-search.ts`
and summarizes it with the configured conversational model. Tavily, Serper, and
Brave require a search-provider key. An optional keyless service would let users
try current-information questions without provisioning another credential.

[Technology Standards](../architecture/Technology-Standards.md) requires an ADR
before adopting a technology outside the listed stack. This proposal records the
choice for maintainer review; it does not declare Parallel an approved standard.

## Proposed decision

Offer `WEB_SEARCH_PROVIDER=parallel` as an explicit opt-in. Use the TypeScript
MCP SDK with Streamable HTTP to call `web_search` on
`https://search.parallel.ai/mcp`, without authentication. Anonymous search uses
Fast mode. Adapt structured results to the existing title, URL, domain, and
snippet contract. Keep the MCP client isolated in `api/parallel-search.ts` and
load it only for the selected provider.

Preserve Tavily as the default, the other provider selections and credentials,
the conversational model configuration, dashboard grounding, and the existing
failure response. Do not add page fetching, automatic provider fallback, model
tool dispatch, persistence, migrations, or changes to authentication.

## Alternatives considered

- Keep only the existing providers: avoids a dependency, but retains the search-key
  requirement for every supported provider.
- Use the authenticated Parallel API: suitable for account-backed usage, but does
  not address the keyless setup goal.
- Implement the MCP wire protocol directly: avoids the SDK dependency, but adds
  protocol, streaming, and lifecycle maintenance to the application.

## Consequences

- Users can opt into free-tier live search without a Parallel account or key.
- The server gains an MCP SDK dependency and another external service boundary.
- Free-tier limits may interrupt search. The adapter fails through the existing
  search-error path instead of silently changing providers.
- Search requests have a 15-second deadline, propagate cancellation, and close
  the client after completion. Responses must match the expected structured
  schema before entering the existing untrusted-evidence prompt.
- The adapter sends the search question, not the dashboard context payload.
  Questions can still contain sensitive text, so operators must choose whether
  external search is appropriate for their deployment.

## Setup and reversal

See [Parallel web-search setup](../parallel-web-search.md). Restore the previous
provider setting to stop using Parallel; no database change is involved.
