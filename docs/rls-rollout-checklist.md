# RLS Rollout Checklist

Use this one-page operator runbook to roll out Row Level Security (RLS) in production. Execute one phase at a time during an approved maintenance window, stop after any failed check, and do not continue to the next phase until the current phase has been validated and signed off.

## Global production controls

- **Change window:** Confirm maintenance window, on-call coverage, and stakeholder notification before starting.
- **Backup:** Capture a fresh database backup or restore point and record the backup identifier in the change ticket.
- **Connection roles:** Confirm the app backend uses the expected service/table-owner connection and that `anon` and `authenticated` direct-access roles are available.
- **Execution source:** Copy the phase SQL and rollback SQL from `docs/rls-deployment-plan.md`; run only the current phase.
- **Stop criteria:** Roll back immediately if table access, policy counts, UI workflows, or API smoke tests fail.

| Phase | SQL file location | Tables affected | Pre-checks | Deployment steps | Validation tests | Rollback steps |
| --- | --- | --- | --- | --- | --- | --- |
| **1 — Low-risk document tables** | `docs/rls-deployment-plan.md` → Phase 1 Exact SQL and Rollback SQL | `doc_folders`, `doc_files`, `smp_documents` | Verify backup exists; confirm all three tables exist; capture baseline `pg_class.relrowsecurity` and `pg_policies`; prepare disposable document/folder test data. | Start transaction; grant `SELECT` to `anon`/`authenticated`; grant writes and sequence usage to `authenticated`; enable RLS; create read-all and authenticated-write policies; commit. | Confirm `relrowsecurity=true` and `relforcerowsecurity=false`; confirm exactly two policies per table; verify `anon` can read and cannot write; verify `authenticated` can create/update/delete disposable rows; smoke-test O&M document tree, file upload/download/delete, and SMP document CRUD. | Run Phase 1 Rollback SQL; confirm policies are removed and RLS is disabled on the three tables; re-run document/SMP smoke tests; record incident notes and stop rollout. |
| **2 — Planning and scheduling tables** | `docs/rls-deployment-plan.md` → Phase 2 Exact SQL and Rollback SQL | `equipment`, `tasks`, `existing_facilities_maintenance`, `gantt_tasks`, `gantt_dependencies`, `gantt_projects` | Phase 1 must be signed off; verify backup/restore point is still valid; confirm table and sequence names; capture baseline RLS/policy state; prepare disposable task, EFM, Gantt task, dependency, and project records. | Start transaction; grant read access to `anon`/`authenticated`; grant writes and sequence usage to `authenticated`; enable RLS on all Phase 2 tables; create read-all and authenticated-write policies; commit. | Confirm RLS enabled without force; confirm exactly two policies per table; verify `anon` read-only behavior; verify `authenticated` write behavior; smoke-test task list/update/import/export, EFM list/create/update/delete/import/reset, and Gantt load/save/delete/reorder/dependency/project flows. | Run Phase 2 Rollback SQL; confirm policies are removed and RLS is disabled on Phase 2 tables; re-run ODM, EFM, and Gantt smoke tests; keep Phase 1 in place unless Phase 1 is also failing. |
| **3 — Governance and escalation tables** | `docs/rls-deployment-plan.md` → Phase 3 Exact SQL and Rollback SQL | `governance_facilities`, `governance_milestone_state`, `governance_uploads`, `governance_files`, `mw_inspections`, `mw_compliance`, `mw_escalations` | Phases 1 and 2 must be signed off; verify backup/restore point; confirm table and sequence names; capture baseline RLS/policy state; prepare disposable governance upload/file and MW inspection test records. | Start transaction; grant read access to `anon`/`authenticated`; grant writes and sequence usage to `authenticated`; enable RLS on all Phase 3 tables; create read-all and authenticated-write policies; commit. | Confirm RLS enabled without force; confirm exactly two policies per table; verify `anon` read-only behavior; verify `authenticated` write behavior; smoke-test governance facility/milestone/upload/file flows, MW import/list/detail/update/delete/reset, and compliance/escalation dashboard visibility. | Run Phase 3 Rollback SQL; confirm policies are removed and RLS is disabled on Phase 3 tables; re-run governance and MW smoke tests; leave prior phases enabled unless their validations fail. |

## Final sign-off

- Record completed phase, operator, timestamp, backup identifier, SQL source, validation results, and rollback status in the change ticket.
- Monitor application logs, database errors, and user-reported access issues for at least one business cycle after each phase.
- After all phases remain stable, schedule a separate hardening change for tenant-, organization-, facility-, owner-, or uploader-scoped policies; do not enable `FORCE ROW LEVEL SECURITY` until backend and migration roles are tested under RLS.
